## 2. ПОЧЕМУ JETPACK COMPOSE, А НЕ XML?

| Критерий | XML + View (устаревший) | Jetpack Compose (современный) |
|:---|:---|:---|
| **Подход** | Императивный (находим элементы, меняем свойства) | Декларативный (UI — функция состояния) |
| **Код** | Разделение: XML + Java/Kotlin | Единый код на Kotlin |
| **Перерисовка** | Ручное обновление | Автоматическая рекомпозиция |
| **Сложность** | Много шаблонного кода (`findViewById`) | Минимальный код |
| **Статус** | Легаси (поддержка сохраняется) | **Основной** (рекомендованный Google) |

import androidx.compose.ui.Modifier

/**

 *

class MainActivity : ComponentActivity() {

    /**
     * Вызывается при создании Activity.
     * Устанавливает Compose-содержимое экрана.
     *
     * @param savedInstanceState Сохранённое состояние (если есть)
     */
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            HelloTheme {
                // TODO: Измените вызов Greeting на вашу реализацию

                    modifier = Modifier.fillMaxSize(),

                    Greeting("Android")

            }
        }
    }
}

/**
 * Composable-функция, отображающая приветствие.
 *
 * @param name Имя пользователя (или "Android" по умолчанию)
 * @param modifier Модификатор для стилизации
 */
@Composable
fun Greeting(name: String, modifier: Modifier = Modifier) {
    // TODO: Измените текст на "Моё первое приложение"
    // TODO: Добавьте второе Text с вашим именем
    // TODO: Измените цвета и отступы
    Text(
        text = "Hello $name!",
        modifier = modifier
    )
}

/**
 * Предпросмотр UI в Android Studio.
 * Позволяет видеть изменения без запуска эмулятора.

    }
}

## 6. ТРЕБОВАНИЯ К ОФОРМЛЕНИЮ

### 6.1. Требования к коду

1. **Документирование кода (KDoc):**
   - Все классы должны иметь **KDoc-комментарий** (`/** ... */`) с описанием назначения класса, автором и версией.
   - Все `@Composable`-функции должны иметь **KDoc-комментарий** с описанием назначения и параметров.

2. **Стиль кода:**
   - Следуйте официальному **Kotlin Coding Conventions**.
   - Используйте осмысленные названия переменных и функций.
   - Используйте `Modifier` для стилизации (не смешивайте с атрибутами стилей).

3. **Пример документирующего комментария:**

```kotlin
/**
 * Composable-функция, отображающая карточку профиля пользователя.
 *
 * @param name Имя пользователя, отображаемое в карточке.
 * @param group Группа пользователя.
 * @param modifier Модификатор для настройки внешнего вида.
 *
 * @author Иванов Иван (ПИ-301)
 * @since 2026-09-03
 */
@Composable
fun ProfileCard(
    name: String,
    group: String,
    modifier: Modifier = Modifier
) {
    // ...
}
```
