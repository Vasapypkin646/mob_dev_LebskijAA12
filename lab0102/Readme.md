        modifier = modifier.padding(16.dp)

## 5. ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

### 1. Что такое Jetpack Compose и в чём его отличие от XML-вёрстки?

**Jetpack Compose** — современный декларативный UI-фреймворк для Android от Google. Вместо описания интерфейса в XML и последующего поиска элементов через `findViewById`, весь UI описывается функциями на Kotlin, помеченными `@Composable`.

Ключевые отличия:

| Критерий | XML + View | Jetpack Compose |
|:---|:---|:---|
| Стиль | Императивный | Декларативный |
| Код | XML + Kotlin (раздельно) | Единый Kotlin-код |
| Обновление | Ручное (`setText`, `setVisibility`) | Автоматическая рекомпозиция |
| Шаблонность | Много boilerplate | Минимум кода |
| Файлы layout | Обязательны | Отсутствуют |

### 2. Что такое @Composable-функция? Чем она отличается от обычной функции?

`@Composable` — аннотация, помечающая функцию, которая описывает часть UI. Такие функции:

- не возвращают значение (тип возврата `Unit`, но фактически описывают UI-дерево);
- могут вызываться только из других `@Composable`-функций;
- участвуют в рекомпозиции — Compose сам вызывает их повторно при изменении состояния;
- компилируются специальным плагином Compose-компилятора (добавляется параметр `Composer`).

Обычная функция — это просто вычисление, она не связана с UI-деревом.

### 3. Что такое Modifier и для чего он используется?

**Modifier** — неизменяемая цепочка настроек внешнего вида и поведения Compose-элемента. Через `Modifier` задаются:

- размеры (`size`, `fillMaxSize`, `width`);
- отступы (`padding`);
- фон (`background`);
- клики (`clickable`);
- выравнивание (`align`);
- границы (`border`), форма (`clip`) и т.д.

Пример: `Modifier.padding(16.dp).fillMaxSize().background(Color.Gray)`.

Модификаторы применяются **по цепочке** — порядок важен.

### 4. Что такое рекомпозиция и как она работает в Compose?

**Рекомпозиция** — автоматический повторный вызов `@Composable`-функций при изменении данных, от которых они зависят. Compose отслеживает, какие функции читают какое состояние, и перерисовывает только те части UI, где состояние изменилось. Это делает обновление интерфейса эффективным и не требует ручного поиска элементов и установки новых значений.

### 5. Для чего нужна аннотация @Preview?

`@Preview` — аннотация, которая позволяет Android Studio отображать предпросмотр Composable-функции **без запуска эмулятора или устройства**. Это ускоряет разработку: изменения видны прямо в IDE. У аннотации есть параметры, например:

- `showBackground = true` — рисовать фон;
- `name = "..."` — имя превью;
- `device = "..."` — эмулировать конкретное устройство;
- `uiMode`, `locale` — тестировать разные конфигурации.

### 6. Почему Google рекомендует использовать Jetpack Compose вместо XML?

- **Меньше кода:** одна функция вместо XML + кода Activity/Fragment.
- **Меньше ошибок:** нет `findViewById` и `NullPointerException` из-за разметки.
- **Декларативность:** UI = функция от состояния, легко тестировать.
- **Современные возможности:** анимации, темы, adaptive-layout из коробки.
- **Интеграция с Kotlin:** type-safety, лямбды, корутины.
- **Поддержка Google:** Compose — основной рекомендованный подход для новых проектов.

### 7. Какова структура Compose-проекта?

Основное отличие — **отсутствие XML-разметки**. Весь UI описывается в `MainActivity.kt` (или других Kotlin-файлах) через `@Composable`-функции. Каталог `res/layout/` отсутствует. Тема приложения (цвета, типографика) вынесена в `ui/theme/` (`Color.kt`, `Theme.kt`, `Type.kt`). Остальные части проекта (`AndroidManifest.xml`, `build.gradle.kts`, ресурсы `res/values/`) остаются похожими на классический Android-проект.

### 8. Что такое State и remember в Compose?

**State** — объект, хранящий значение, при изменении которого Compose перерисовывает зависящие от него Composable-функции. Объявляется через `mutableStateOf`:

```kotlin
var count by remember { mutableStateOf(0) }
```

**remember** — функция, которая сохраняет значение между рекомпозициями. Без `remember` при каждой рекомпозиции переменная создавалась бы заново, и состояние терялось. Например:

```kotlin
var count by remember { mutableStateOf(0) }
Button(onClick = { count++ }) {
    Text("Нажато: $count раз")
}
```

При клике состояние меняется, и Compose автоматически перерисовывает только этот `Text`.

## 6. С какими сложностями столкнулись

1. **Сложность:** Поначалу было непривычно, что UI описывается прямо в Kotlin-коде, а не в отдельном XML-файле.
   - **Решение:** Изучил документацию и примеры на developer.android.com/jetpack/compose, разобрал структуру проекта.

2. **Сложность:** При настройке эмулятора не хватало памяти — приложение стартовало с задержкой.
   - **Решение:** Увеличил RAM виртуального устройства до 4 ГБ в настройках AVD и включил аппаратное ускорение графики.

3. **Сложность:** Не сразу было понятно, что `Modifier` применяется по цепочке и порядок вызовов важен.
   - **Решение:** Поэкспериментировал с разными порядками `padding` и `fillMaxSize` — стало очевидно, что модификаторы оборачивают элемент снаружи внутрь.

4. **Сложность:** При коммите в Git случайно попал каталог `.idea/` и файл `local.properties`.
   - **Решение:** Добавил стандартный `.gitignore` для Android-проекта и почистил индекс командой `git rm --cached -r .idea`.
